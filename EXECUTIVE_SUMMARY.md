
# Solution Executive Summary

The AI Data Analyst & Business Intelligence Agent is a local application designed to help an e-commerce or retail business explore structured customer, order and product information through an interactive dashboard and natural-language questions. The objective is to make routine business analysis accessible without requiring users to write SQL or Python queries.

The solution uses Python as the primary programming language. Pandas handles data ingestion, validation, cleaning, transformations and business calculations. The application reads three CSV files representing customers, products and orders. During ingestion, it removes duplicate primary keys, converts date and numeric columns to suitable types, handles missing quantity, price and discount values, validates customer and product references, and calculates net line revenue using quantity multiplied by unit price after discount. A SQLite database is also initialized from the cleaned source tables to demonstrate relational data storage.

The application follows a frontend-backend architecture with two main layers. The Streamlit frontend provides the user interface, displaying key performance indicators for revenue, orders, purchasing customers and average order value. It also presents monthly revenue, revenue by category, top products and customer metrics through Plotly charts and tables. Users can enter natural-language questions through the dashboard and view the resulting analysis. The FastAPI backend provides REST API endpoints for health checks, sales metrics, monthly revenue, category revenue, top products, customer metrics and natural-language questions. The Streamlit frontend communicates with these backend endpoints using HTTP requests through the Python `requests` library. This separation keeps the user interface independent of the backend business logic.

The backend uses separate analytics and agent modules to manage business calculations and question processing. Pandas performs the calculations, while SQLite provides relational data persistence. Pydantic validates incoming question requests, and FastAPI handles API routing and responses. This modular structure separates presentation, API handling, analytics and AI-related functionality.

The AI analyst uses a controlled tool-calling design. A natural-language question is mapped to one of a fixed set of Python functions, such as sales metrics, monthly revenue, category revenue, top products, customer metrics or revenue-decline analysis. When an OpenAI API key is configured, an LLM (default model setting: `gpt-4o-mini`) assists with selecting the appropriate tool. The selected tool name is checked against an allow-list before execution. The LLM is not permitted to invent figures, execute arbitrary SQL or directly access the database. If the provider is unavailable or no API key is configured, rule-based routing provides a local fallback. All numerical outputs are computed from the underlying dataset.

For multi-step analysis, the application compares the latest available month with the preceding calendar month. It examines revenue, order count and average order value, then compares category and product revenue changes to highlight the weakest contributors. This provides evidence for further investigation rather than claiming that correlation proves the cause of a decline. Dynamic chart requests retrieve the relevant monthly or category data and render visualizations from the computed results.

Reliability is addressed through input validation, controlled tool execution, unsupported-question responses, exception handling and automated tests. The tests cover data loading, revenue calculations, rankings, customer metrics, multi-step analysis, known question routing and unsupported input. The README documents project setup, technologies, API endpoints, model usage, testing and limitations. The application can be run using separate terminals for the FastAPI backend and Streamlit frontend.

The included retail dataset is synthetic and is intended to make the project runnable and independently testable. Before using the application for real business decisions, the sample files should be replaced with approved company data and the cleaning rules reviewed with stakeholders. The current implementation does not include authentication, production deployment hardening or causal analysis using inventory, marketing and website-traffic data. Overall, the project demonstrates an end-to-end, data-grounded AI analytics workflow with a connected Streamlit frontend, FastAPI backend, controlled AI-assisted tool selection and deterministic business calculations.
